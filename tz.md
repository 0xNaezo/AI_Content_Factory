# ТЗ: AI Content Factory

Версия 0.1 · 29.09.2026 · Черновик
Архитектура, стек и реализация описываются в отдельном техническом документе. Числовые пороги в этом ТЗ — стартовые значения, уточняются при реализации.

## 1. Суть

Система принимает сырые материалы в любом формате, определяет, к какому бренду они относятся, готовит адаптированные публикации под каждую площадку бренда (текст и визуал), отправляет их человеку на одобрение и публикует по расписанию. По расписанию собирает email-дайджест. Одна инсталляция обслуживает много брендов.

**Основной сценарий:** автор отправляет голосовое боту → система расшифровывает и выделяет суть → определяет бренд → создаёт пакет вариантов под площадки с картинками → редактор в Telegram правит или одобряет → варианты уходят в слоты расписания → публикуются → попадают в дайджест и отчёты.

**Цели проекта**

- Портфолио-кейс: показать, что команда строит тяжёлые продакшн-системы автоматизации. Система работает вживую на демо-брендах.
- Продукт должен выглядеть правдоподобным white-label решением для маркетингового агентства: N клиентов агентства = N брендов.

**Целевой заказчик:** маркетинговые и SMM-агентства; компании с несколькими брендами или направлениями; e-commerce с несколькими аккаунтами.

## 2. Термины

| Термин           | Значение                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------- |
| Бренд            | Единица обслуживания: свой голос, визуал, площадки, расписание, люди                     |
| Профиль бренда   | Настройки бренда (брендбук как конфиг), раздел 5.4                                       |
| Площадка         | Канал публикации: Telegram-канал, блог, email, соцсети                                   |
| Материал         | Исходник от автора: текст, голос, файл, ссылка, картинка                                 |
| Пакет            | Всё, что создано из одного материала для одного бренда                                   |
| Вариант          | Публикация под одну площадку внутри пакета (текст + визуал)                              |
| Слот             | Время в расписании площадки, куда ставится вариант                                       |
| Дайджест         | Email-выпуск бренда, собранный из публикаций за период                                   |
| Preview-площадка | Площадка без реальной публикации: вариант создаётся и показывается «как будет выглядеть» |

Один пользователь может иметь разные роли в разных брендах.

| Присылать материалы                          | ✓     | ✓               | ✓          | ✓              | —           | демо  |
| Одобрять, править, отклонять                 | ✓     | ✓               | ✓          | —              | —           | —     |
| Настраивать профиль бренда                   | ✓     | ✓               | —          | —              | —           | —     |
| Подключать площадки, расписание              | ✓     | ✓               | —          | —              | —           | —     |
| Управлять пользователями бренда              | ✓     | ✓               | —          | —              | —           | —     |
| Видеть календарь и отчёты                    | ✓     | ✓               | ✓          | свои материалы | ✓           | —     |
| Стоп-кран публикаций                         | ✓     | свой бренд      | свой бренд | —              | —           | —     |

- **Наблюдатель** — клиент агентства: видит календарь и отчёты своего бренда, ничего не меняет.
- **Гость** — посетитель демо-режима (раздел 10).

## 4. Границы

**MVP**

- Приём материалов: Telegram-бот, email, веб-форма.
- Форматы: текст, голос, изображения, PDF, DOCX, XLSX/CSV, URL.
- Реальная публикация: Telegram-канал, блог, email-дайджест.
- Preview-площадки: LinkedIn, Instagram, Facebook, X.
- Одобрение в Telegram. Веб-панель только на просмотр: календарь, очередь, журнал, отчёты.
- Онбординг бренда из существующих постов.
- 3 демо-бренда, гостевой демо-режим.

**Этап 2**

- Реальная публикация в LinkedIn, Instagram, Facebook, X.
- Действия в веб-панели: одобрение, правка, перенос в календаре.
- Карусели и короткие видео.
- A/B-варианты первой строки с выбором победителя по метрикам.
- Брендированный кабинет клиента агентства.

**Вне скоупа**

- Ответы на комментарии и личные сообщения.
- Рекламные кампании и платное продвижение.
- Биллинг клиентов агентства.
- Длинные видео.

## 5. Функциональные требования

### 5.1 Приём материалов (IN)

- **IN-1 Каналы.** Telegram-бот (личные сообщения); email на адрес инсталляции (тема, текст, вложения); веб-форма (текст, файлы, выбор бренда).
- **IN-2 Типы и лимиты.**

  | Тип               | Лимит                                         | Особенности                                            |
  | ----------------- | --------------------------------------------- | ------------------------------------------------------ |
  | Текст             | до 20 000 символов                            | —                                                      |
  | Голосовое / аудио | до 10 мин                                     | —                                                      |
  | Изображения       | JPG/PNG/WebP, до 20 МБ, до 10 шт. в материале | могут использоваться как визуал                        |
  | PDF, DOCX         | до 20 МБ, до 30 страниц                       | —                                                      |
  | XLSX, CSV         | до 500 строк                                  | строка = отдельный материал, шаблон колонок фиксирован |
  | URL               | публичная страница                            | извлекается основной текст без меню и рекламы          |

- **IN-3 Подсказки автора** (необязательны): бренд, площадки, дата и время, тон, «только в дайджест», «срочно». Задаются подписью в свободной форме или кнопками бота.
- **IN-4 Подтверждение.** Не позже чем через 10 с автор получает ID материала и что распознано (тип, объём).
- **IN-5 Склейка.** Сообщения одного автора в пределах 60 с (альбом, текст + фото) объединяются в один материал.
- **IN-6 Дубли.** Идентичный или почти идентичный материал за последние 30 дней → предупреждение со ссылкой на исходный и вопрос «создать новый?».
- **IN-7 Отказ.** Пустой, нечитаемый или неподдерживаемый материал отклоняется с понятной причиной.
- **IN-8 Неизвестный автор.** Отправитель без доступа к брендам: материал не принимается, отправителю — как получить доступ, админу — уведомление.
- **IN-9 Таблицы.** Колонки шаблона: бренд, тема или текст, ссылка, площадки, дата. Ошибочные строки возвращаются отчётом с номерами строк, корректные обрабатываются.

### 5.2 Разбор материала (EX)

- **EX-1 Приведение к тексту:** голос → расшифровка; документ → текст; URL → основной текст; изображение → описание содержимого (само изображение сохраняется как возможный визуал).
- **EX-2 Выжимка:** главная мысль, факты и цифры, цитаты, призыв к действию, ссылки.
- **EX-3 Достаточность.** Если содержания мало для публикации — автору один уточняющий вопрос. Без ответа за 2 ч пакет создаётся с пометкой «мало исходных данных».
- **EX-4 Язык** исходника определяется автоматически; контент создаётся на языке (языках) бренда.
- **EX-5** Исходник и выжимка сохраняются и доступны редактору из карточки пакета.

### 5.3 Определение бренда (RT)

- **RT-1 Порядок:** явная подсказка автора → привязка автора, если у него один бренд → сопоставление содержания с профилями брендов.
- **RT-2 Уверенность.** Если уверенность ниже порога, автор получает кнопки: топ-3 бренда и «другой».
- **RT-3 Несколько брендов.** Автор может направить материал в несколько брендов; для каждого создаётся независимый пакет.
- **RT-4 Вне тематики.** Если материал не подходит ни одному бренду, система спрашивает автора и не генерирует молча.
- **RT-5 Перенаправление.** Редактор может перенаправить пакет в другой бренд до публикации; пакет создаётся заново.

### 5.4 Профиль бренда (BP)

- **BP-1 Состав профиля.**

  | Блок                  | Поля                                                                                               |
  | --------------------- | -------------------------------------------------------------------------------------------------- |
  | Основное              | название, описание, ниша, целевая аудитория, язык(и), часовой пояс                                 |
  | Голос                 | тон, стиль, обращение (ты/вы), эмодзи да/нет, разрешённые и запрещённые слова и темы               |
  | Обязательные элементы | CTA, ссылки с метками, хэштеги, дисклеймеры, подпись                                               |
  | Визуал                | палитра, стиль изображений, логотип и правила размещения, запреты (люди, текст на картинке и т.п.) |
  | Эталоны               | 5–20 примеров удачных постов, антипримеры                                                          |
  | Площадки              | подключённые площадки, переопределение формата на площадку                                         |
  | Расписание            | слоты по площадкам, лимит постов в день, минимальный интервал                                      |
  | Одобрение             | кто одобряет, автопубликация да/нет по площадкам, дедлайн одобрения                                |
  | Бюджет                | месячный лимит затрат на AI                                                                        |

- **BP-2 Версии.** Профиль версионируется; каждый пакет хранит версию профиля, по которой создан.
- **BP-3 Онбординг.** Новый бренд заводится настройкой, без доработки системы. Менеджер даёт 5–10 ссылок или текстов существующих постов → система предлагает черновик профиля (тон, темы, эталоны, визуальный стиль) → менеджер правит и подтверждает.

### 5.5 Генерация пакета (GN)

- **GN-1** Для каждой активной площадки бренда создаётся вариант по формату площадки (раздел 6).
- **GN-2 Без выдумок.** Варианты опираются только на исходник и профиль бренда. Запрещено добавлять факты, цифры, цены, даты, обещания, имена, которых нет в исходнике или профиле. Спорные места помечаются для редактора.
- **GN-3 Визуал.** Присланное изображение, адаптированное под пропорции площадки, или сгенерированное в стиле бренда; логотип по правилам профиля. Запрещено: реальные люди, чужие бренды, логотипы и персонажи, текст с ошибками на изображении.
- **GN-4** По запросу — 3 варианта заголовка или первой строки.
- **GN-5 Автопроверки** (результат виден в карточке): лимиты длины; запрещённые слова и темы; наличие обязательных элементов; рабочие ссылки; язык; соответствие фактов исходнику; повтор темы (похожая публикация бренда за 14 дней).
- **GN-6** Если обязательная проверка не пройдена, система исправляет вариант сама (до 2 попыток). Не удалось — вариант уходит на одобрение с красной пометкой и причиной.
- **GN-7 Время готовности** (от приёма до карточки у редактора): текст и URL — до 3 мин; голос и документы — до 7 мин.
- **GN-8** Затраты на AI по каждому пакету считаются и сохраняются.

### 5.6 Одобрение (AP)

- **AP-1 Карточка пакета** приходит в Telegram редакторам бренда: бренд, исходник (свёрнут), варианты по площадкам с визуалом, результаты проверок, предлагаемые слоты.
- **AP-2 Действия:** одобрить всё · одобрить площадку · отклонить (причина из списка + текст) · править текст вручную · переделать с комментарием («короче», «без эмодзи») · перегенерировать визуал · заменить визуал своим · сменить время · убрать площадку · опубликовать сейчас.
- **AP-3** Каждая правка создаёт новую версию варианта; история версий доступна.
- **AP-4 Обратная связь.** Ручные правки и причины отклонений сохраняются в профиль бренда как эталоны и антиэталоны и учитываются в следующих генерациях. Менеджер может просматривать и удалять накопленные примеры.
- **AP-5 Сроки.** Не одобрено за 12 ч до слота — напоминание; за 1 ч — повтор. Не одобрено к слоту — не публикуется, переносится в следующий свободный слот, редактор уведомлён.
- **AP-6 Автопубликация** (настройка бренда и площадки, по умолчанию выключена): публикация без одобрения только при пройденных проверках, иначе обычное одобрение.
- **AP-7** Достаточно одного одобрения от любого редактора бренда. Карточка обновляется у всех: видно, кто и что сделал.

### 5.7 Расписание и публикация (PB)

- **PB-1 Постановка.** Одобренный вариант ставится на время из подсказки автора; если его нет — в ближайший свободный слот площадки; по кнопке — «сейчас».
- **PB-2** Соблюдаются лимит постов в день и минимальный интервал; при конфликте — следующий свободный слот.
- **PB-3** Публикация в назначенное время с точностью ±1 мин по часовому поясу бренда.
- **PB-4 Статусы варианта:** запланирован → публикуется → опубликован (со ссылкой на пост) или ошибка.
- **PB-5 Ошибка площадки.** Автоматические повторы в течение 30 мин, затем уведомление редактору с причиной и кнопками «повторить» / «перенести» / «отменить».
- **PB-6** Ни при каких сбоях вариант не публикуется дважды.
- **PB-7** До публикации: перенос, правка, отмена. После: правка и удаление там, где площадка это позволяет.
- **PB-8 Preview-площадки** проходят весь цикл и получают статус «опубликован (preview)» с рендером «как будет выглядеть».
- **PB-9 Стоп-кран.** Пауза публикаций на уровне площадки, бренда или всей системы. Запланированное не теряется; при снятии паузы — выбор: опубликовать просроченное или переназначить слоты.

### 5.8 Дайджест (DG)

- **DG-1** Для брендов с email: выпуск по расписанию (ежедневно или еженедельно, день и время в профиле).
- **DG-2 Наполнение:** публикации бренда за период + материалы с пометкой «в дайджест» + (опционально) темы из внешних источников бренда (RSS-ленты и сайты, до 10), отобранные по релевантности, без повторов прошлых выпусков.
- **DG-3 Структура** по шаблону бренда: тема письма, прехедер, вступление, 3–7 блоков, CTA, подвал с отпиской.
- **DG-4** Выпуск готов за 2 ч до отправки и проходит одобрение как пакет, плюс кнопка «тестовая отправка себе». Не одобрен к сроку — не отправляется (или автоотправка по настройке бренда).
- **DG-5 Подписчики.** Форма подписки на сайте или в блоге бренда с подтверждением email; отписка в один клик; отписавшиеся больше не получают писем; удаление данных подписчика по запросу.
- **DG-6 Метрики выпуска:** отправлено, доставлено, открытия, клики, отписки — в пределах того, что отдаёт почтовый сервис.
- **DG-7** Если за период набралось меньше 2 блоков, выпуск пропускается, редактор уведомлён.

### 5.9 Аналитика и отчёты (AN)

- **AN-1 Веб-панель** (просмотр, доступ по роли): календарь (запланировано, опубликовано, ошибки по брендам и площадкам); очередь на одобрении; журнал материалов со сквозной историей; отчёты.
- **AN-2 Метрики** (фильтры: бренд, площадка, период):
  - материалов принято, пакетов создано;
  - % одобренных без правок, среднее число итераций;
  - время «приём → карточка» и «приём → публикация»;
  - опубликовано, ошибки публикации;
  - затраты на AI на пакет и на бренд;
  - метрики площадок (просмотры, реакции, клики) — где площадка их отдаёт.
- **AN-3** Еженедельный отчёт по бренду менеджеру и наблюдателю в Telegram или на email; для агентства это готовый отчёт клиенту.
- **AN-4** Экспорт отчётов в CSV.

### 5.10 Администрирование (AD)

- **AD-1** Управление брендами, профилями, площадками, расписаниями.
- **AD-2 Пользователи.** Приглашение по ссылке в Telegram-бота с ролью и набором брендов; отзыв доступа действует сразу.
- **AD-3 Аудит.** Неизменяемый журнал: кто, когда, что сделал (приём, одобрение, правка, публикация, изменение настроек).
- **AD-4 Бюджет AI.** Месячный лимит на бренд. При 80% — предупреждение; при 100% генерация останавливается, приём продолжается (материалы ждут в очереди).
- **AD-5 Состояние системы.** Админ получает оповещение, если площадка недоступна, доля ошибок генерации выше порога или растёт очередь.

## 6. Форматы площадок

Лимиты сверить с правилами площадок на момент реализации. Формат любой площадки можно переопределить в профиле бренда.

| Площадка       | MVP                          | Что создаётся                                                      | Объём                                     | Визуал                      |
| -------------- | ---------------------------- | ------------------------------------------------------------------ | ----------------------------------------- | --------------------------- |
| Telegram-канал | публикация                   | пост                                                               | до 1024 символов с картинкой, до 4096 без | 1 изображение, 16:9 или 1:1 |

## 7. Жизненный цикл

**Материал**

| Статус         | Значение                             | Переходы                  |
| -------------- | ------------------------------------ | ------------------------- |
| Принят         | получен, ID выдан                    | Разобран, Отклонён        |
| Разобран       | приведён к тексту, выжимка готова    | Ждёт уточнения, Направлен |
| Ждёт уточнения | вопрос автору (бренд или содержание) | Направлен, Отклонён       |
| Направлен      | бренд(ы) определены                  | → создание пакетов        |
| Отклонён       | финальный, с причиной                | —                         |

**Вариант**

| Статус             | Значение                            | Переходы                                 |
| ------------------ | ----------------------------------- | ---------------------------------------- |
| Черновик           | создан, идут автопроверки           | На одобрении                             |
| На одобрении       | ждёт редактора                      | На доработке, Одобрен, Отклонён          |
| На доработке       | переделка по комментарию            | На одобрении                             |
| Одобрен            | готов к постановке                  | Запланирован                             |
| Запланирован       | стоит в слоте                       | Публикуется, Перенесён, Отменён          |
| Перенесён          | пропустил слот или конфликт         | Запланирован                             |
| Публикуется        | идёт отправка на площадку           | Опубликован, Ошибка                      |
| Ошибка             | повторы исчерпаны                   | Запланирован, Отменён                    |
| Опубликован        | финальный, со ссылкой (или preview) | правка/удаление, если площадка позволяет |
| Отклонён / Отменён | финальные                           | —                                        |

Отменить можно из любого статуса до «Публикуется».

## 8. Нефункциональные требования

- **Сохранность.** Принятый материал не теряется ни при каких сбоях; прерванная обработка продолжается с места сбоя.
- **Без дублей.** Повторная доставка одного и того же сообщения не создаёт второй материал или вторую публикацию.
- **Изоляция брендов.** Пользователь видит только свои бренды в боте, панели и отчётах; данные и настройки брендов не пересекаются.
- **Масштаб.** Не менее 10 брендов и 1000 материалов в месяц без изменения системы. Таблица на 500 строк обрабатывается без потерь и дублей, все пакеты созданы за 60 мин.
- **Трассировка.** У каждого материала сквозной ID. По нему видна полная история: что пришло, что сгенерировано, кто одобрил, куда и когда опубликовано, сколько стоило.
- **Измеримое качество.** Эталонный набор (не менее 30 материалов на 3 бренда) прогоняется при каждом изменении правил генерации; результаты сравниваются с прошлым прогоном (проверки, длины, соответствие фактов).
- **Безопасность.** Доступ только по приглашению. Ключи площадок недоступны пользователям и не попадают в логи и сообщения.
- **Приватность.** О подписчиках хранятся только email и статус подписки; удаление по запросу.
- **Деградация.** При недоступности генерации приём продолжается, материалы ждут в очереди.
- **Язык интерфейса** — английский (международное портфолио); контент — на языке бренда.

## 9. Ограничения и допущения

- Без регистрации бизнеса и платных подписок. AI-модели оплачиваются по факту использования (допущение, подтвердить).
- Площадки, требующие бизнес-верификации, платного API или ревью приложения, в MVP работают только в режиме preview.
- Демо-бренды вымышленные: никаких реальных брендов, логотипов, людей.
- Контент соблюдает правила площадок; email отправляется только подтверждённым подписчикам.
- Платформа — n8n. Архитектура, стек и выбор моделей — в техническом документе.

## 10. Демо и упаковка кейса

- **3 демо-бренда** разных ниш и тонов: кофейня (дружелюбный), B2B SaaS (экспертный), фитнес-студия (энергичный). Один бренд двуязычный.
- **Живые площадки:** у каждого бренда публичный Telegram-канал, раздел блога и дайджест с подпиской — результат можно открыть и посмотреть.
- **Контент-поток** минимум 2 недели регулярных публикаций до показа кейса, чтобы в метриках были реальные цифры.
- **Гостевой режим.** Любой может прислать боту свой материал и получить пакет-превью без публикации: для демо-бренда или для временного бренда, собранного из описания бизнеса одной фразой.
  - лимит 3 материала в сутки на пользователя;
  - отдельный месячный бюджет на гостевой режим;
  - отказ на оскорбительный и незаконный контент.
- **Видео на 2–3 мин:** голосовое → бренд определён → 4 площадки → правка комментарием → одобрение → пост в канале → блок в дайджесте.
- **Страница кейса:** задача, возможности, цифры из отчётов (материалов обработано, % одобренных без правок, время до публикации, стоимость пакета), схема из технического документа.

## 11. Критерии приёмки MVP

- [ ] Голосовое на 2 мин → карточка у редактора не позже 7 мин; варианты для всех площадок бренда, визуалы в нужных пропорциях.
- [ ] PDF без указания бренда → бренд определён верно минимум в 9 из 10 тестовых материалов; при низкой уверенности автор получает вопрос.
- [ ] Таблица на 500 строк → 0 потерь, 0 дублей, ошибочные строки перечислены с номерами.
- [ ] В выборке из 30 вариантов эталонного набора нет фактов, которых нет в исходнике и профиле (ручная проверка).
- [ ] «Переделать с комментарием» учитывает комментарий; правка попадает в обратную связь бренда.
- [ ] Вариант, не одобренный к слоту, не публикуется и переносится; редактор уведомлён.
- [ ] Площадка недоступна в момент публикации → повторы → уведомление → ручной повтор публикует ровно один раз.
- [ ] Стоп-кран останавливает публикации не позже чем через 1 мин.
- [ ] Дайджест: тестовая отправка, одобрение, рассылка; отписка в один клик работает.
- [ ] Пользователь бренда A не видит ничего из бренда B ни в боте, ни в панели, ни в отчётах.
- [ ] Новый бренд заведён через онбординг без изменений в системе за 30 мин.
- [ ] По ID любого материала видна полная история и стоимость.
- [ ] Бюджет 100% → генерация остановлена, приём продолжается.
- [ ] Гостевой режим: лимиты работают, реальных публикаций нет.

## 12. Открытые вопросы

1. Подключать ли в MVP реальную публикацию хотя бы в одну соцсеть сверх Telegram, блога и email? - нет, их трех достаточно.

4. Почтовый сервис: хватит ли бесплатного лимита на демо-базу подписчиков? должно хватить
5. Язык интерфейса: только EN или EN + RU/UK? ТОЛЬКО EN
6. Нужна ли веб-форма в MVP, если есть Telegram и email? - нет
